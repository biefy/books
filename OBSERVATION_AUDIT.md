## Executive summary

The observation and experiment sections are functionally written but pedagogically under-finished: of 308 verified findings across 56 chapters, only two chapter groups (day27, day28-30) are clean, and 200 findings are major-or-critical. The single most important theme is that the day01 standard — *provoke the phenomenon, run a command that works verbatim, describe the correct output, explain the why/pitfalls, then tear down* — was applied to day01 alone and dropped almost everywhere else. The dominant defect by a wide margin is "run this and observe" steps with no stated or observable expected output (86 findings), which means a reader literally cannot tell a successful run from a broken one.

## Systematic patterns (cross-cutting)

These weaknesses appear in **both** books, synthesized from the two per-book pattern lists and the bpftrace sweep.

1. **No stated expected output or success criterion (~46 chapters; 86 findings).** The most pervasive flaw, spanning nearly every chapter of both books (linux-net day02-day30, ebpf day01-day26). A command is shown but the reader is never told what a correct run looks like, so they cannot distinguish success, partial failure, and an empty result. This is the highest-leverage thing to fix.

2. **Observation has no trigger / fires on an idle box (~25 chapters; 31 "won't-fire" findings).** linux-net drops day01's "generate load first" discipline (day01, 02, 03, 06, 10, 11, 14-17, 20, 25, 26, 28, 29); ebpf labs frequently attach a probe with nothing to make it fire. The reader runs the step, sees nothing, and assumes their setup is broken.

3. **Commands that fail verbatim, or fabricated tool output (~20 chapters; 41 broken-command findings).** Two flavors: hardcoded placeholders that don't exist on the reader's box (`eth0`, `192.168.1.1`, `some-target`, fixed PCI handles, kernel-tree-relative paths — linux-net day03/05/07/23/25/27/29), and ebpf's invented verifier/bpftool strings, register types, and instruction offsets that don't match a real 7.x kernel (ebpf day01-05, 14-16, 24, 25). Both leave the reader debugging the book instead of the kernel.

4. **Labs that can't be built/run as printed, and missing prerequisites (~20 chapters; 53 missing-setup findings).** linux-net assumes uninstalled tooling with no note (iperf3, trace-cmd, conntrack, dropwatch, ab, liburing, ynl deps — day02/04/17/19/22/28/29); ebpf ships skeleton/incomplete loaders and omits `make`/skeleton-gen/`vmlinux.h`/toolchain steps (day01, 06, 07, 11-14, 17-20, 23, 25, 26).

5. **No teardown — backgrounded processes, sysctls, qdiscs, and attachments left running (~30 chapters; 37 missing-cleanup findings).** linux-net day02-26+ and ebpf day02-23 diverge from day01's `pkill` convention, leaving state that corrupts the *next* chapter's observations.

6. **Topology that silently bypasses the mechanism being taught (~10 chapters).** Loopback or same-namespace veth, and sending to a locally-owned address, takes a path with no bottleneck, no driver/NAPI/GRO, no ARP, and no wire crossing (linux-net day03/12/16/23/27/30; ebpf network labs, plus `nc -u` that transmits nothing). The reader observes the opposite of the lesson.

7. **Attach race with no `wait` barrier (~8 chapters, linux-net day02/03/06/09/10/14/20/30).** A tracer is backgrounded and the trigger fires before the probe attaches, so the capture is empty even when everything else is correct.

8. **Thin "why" / weak pedagogy (~34 weak-pedagogy + 6 missing-why findings).** Raw integer kernel values shown without decoding, and steps presented without the day01-style rationale (why `timeout`, why `-w /dev/null`).

**Note from the sweep (good news):** all six bpftrace correctness probes — bare `skb->`/`sk->` derefs in fentry/fexit blocks, bare `exit`, uncast pointer subtraction, `%pI4` with `&args->`, CPP-macro field names, and guessed argument names — returned **0 real hits**. Those previously-recurring syntax-level bugs are now clean and need no further work.

## Prioritized roadmap

Fix in this order, mirroring the day01 refinement (correctness first, polish last):

1. **Correctness bugs (critical + broken-command, 41+33 findings).** Replace hardcoded placeholders with derived values (`$IFACE=$(ip route ...)` style), and correct or regenerate every fabricated verifier/bpftool/`bpftrace` output against a real 7.x kernel. Start with the heaviest, most-broken chapters: **ebpf day05, day15, day16, day24/25; linux-net day23, day25, day05.**

2. **Make labs runnable (missing-setup, 53 findings).** Add prerequisite/install notes and complete the unbuildable ebpf skeletons (`make`, skeleton-gen, `vmlinux.h`, toolchain) — **ebpf day06/07/11-14/17-20, day23; linux-net day04/17/19/22/28/29.** A reader who can't build cannot observe anything.

3. **Add triggers so observations aren't empty (won't-fire, 31 findings).** Prepend a load generator / packet trigger and an attach `wait` barrier — **linux-net day02/03/06/10/14-17/20/25/26/29; ebpf attach-then-fire labs.**

4. **State expected output / success criterion (no-expected-output, 86 findings).** The largest bucket and the highest reader impact once commands actually run: for every observe step, describe the correct result and how to read it. Sweep both books end-to-end; this alone touches ~46 chapters.

5. **Add the why and pitfalls (weak-pedagogy + missing-why, 40 findings).** Decode raw kernel integers and explain rationale in the day01 voice (why `timeout`, why `-w /dev/null`).

6. **Polish: teardown and consistency (missing-cleanup + inconsistency, 57 findings).** Append `pkill`/sysctl-restore/qdisc-delete teardown and reconcile cross-chapter inconsistencies so each lab leaves a clean slate for the next.

## How to verify the runtime findings

The 193 runtime-verifiable findings should be confirmed on the test VM (kernel 7.0, bpftrace v0.25) both **before** fixing (to reproduce the empty/broken/wrong-output behavior) and **after** (to confirm the command now runs, the trigger fires, and the described expected output actually appears). One environment nuance to account for so it isn't mistaken for a book bug: some fentry probes — notably `ip_rcv` and `netif_receive_skb` — do not fire on this VM's loopback/virtual-NIC path, so an empty result on *those specific probes* reflects the test topology, not a defect in the chapter; verify those against a trigger that crosses a real device path or flag them as VM-environment-limited rather than rewriting the lab.

# linux-net — detailed findings

## linux-net — patterns

These weaknesses recur across the book's chapters. Chapter lists are exhaustive for each pattern.

1. **No stated expected output / success criterion.** Commands are given with no description of what a correct run looks like, so the reader cannot tell success from failure. Affected: day02, day03, day07, day08, day09, day10, day14, day15, day16, day17, day18, day19, day20, day21, day23, day24, day25, day26, day27, day28, day29, day30.

3. **Attach race / no `wait` barrier.** A tracer or recorder is backgrounded and the trigger fires immediately (or the report runs before the recorder finishes), so the probe is not yet attached / the capture not finalized. Affected: day02, day03, day06, day09, day10, day14, day20, day30.

4. **No teardown — background processes left running, sysctls/qdiscs/state not restored.** Diverges from day01's `pkill` convention. Affected: day02, day03, day05, day06, day07, day10, day12, day14, day15, day16, day17, day18, day19, day20, day21, day22, day23, day24, day25, day26, day30.

6. **Required tooling not installed by default, with no prerequisite note** (iperf3, trace-cmd, conntrack, dropwatch, nginx/ab, liburing, ynl python deps). Affected: day02, day04, day17, day19, day22, day28, day29.

7. **Loopback / single-namespace topology silently bypasses the mechanism being taught** (no bottleneck, no driver/NAPI/GRO, no ARP, frame never crosses the wire). Affected: day03, day12, day16, day23, day27, day30.

8. **Raw integer kernel values printed but never decoded to symbolic names** (NUD states, TCP states, Netfilter hook numbers, TLS optname). Affected: day07, day13, day15, day20, day25.

### Per-chapter findings

#### day01 — Anatomy, lifecycle, and memory layout of struct sk_buff, observed live via bpftrace/perf/pahole.

- [ ] **[major/wont-fire-or-empty]** _Watch drops with reasons (99-105)_ — `perf trace ... -- sleep 5` scopes to the sleeping task, but kfree_skb fires in softirq context, so output is empty; no drop trigger either, and it contradicts Obs3. **Fix:** Make it system-wide and time-boxed like Obs3: `sudo timeout 5 perf trace --no-syscalls -e skb:kfree_skb`. Add a note that an idle box drops almost nothing, so generate drops in another terminal (e.g. `for i in $(seq 1 20); do curl -s --max-time 1 http://localhost:1 >/dev/null; done`).
- [ ] **[minor/weak-pedagogy]** _Trace a packet's headroom journey (118-125)_ — claims "~64 bytes (NET_SKB_PAD)" at ip_rcv, but eth_type_trans already pulled ETH_HLEN, so headroom is ~78 ([64,80) bucket); hides the skb_pull mechanism. **Fix:** Reword to: "You'll see the peak in the [64, 80) bucket — NET_SKB_PAD (64) plus the 14-byte Ethernet header that eth_type_trans() already pulled before ip_rcv, which advanced `data` so the measured headroom grew by ETH_HLEN to ~78. It can be larger on drivers reserving extra (page_pool/XDP)."
- [ ] **[minor/inconsistency]** _Observation 3 — Drop reason histogram (186-191)_ — prose says `SKB_DROP_REASON_NO_SOCKET`, but the tracepoint prints the bare token `NO_SOCKET`; self-contradicts the bare `NOT_SPECIFIED` in the same sentence. **Fix:** Change `SKB_DROP_REASON_NO_SOCKET` to `NO_SOCKET` on line 191.
- [ ] **[minor/weak-pedagogy]** _Observation 1 — Different headrooms by allocator (141-149)_ — labeled an Observation but nothing to run; only asserts values and says "Check skbuff.h". **Fix:** Give a command: `grep -n 'define NET_SKB_PAD' ~/code/linux/include/linux/skbuff.h` (shows `#define NET_SKB_PAD max(32, L1_CACHE_BYTES)` = 64 on x86_64), and tie it to the ~64-byte headroom seen in the ip_rcv histogram.

#### day02 — Tracing a packet up the RX path from the NIC IRQ/softirq through NAPI, GRO, netif_receive_skb, into ip_rcv.

- [ ] **[major/no-expected-output]** _Use ftrace to see the call chain (101-115)_ — trigger is `ping -c 1 8.8.8.8` (ICMP) but the documented leaf is `ip_local_deliver -> tcp_v4_rcv`; the prescribed packet delivers via icmp_rcv, so the reader can't confirm success. **Fix:** End the chain with `-> ip_local_deliver -> icmp_rcv` (reply handled by icmp_rcv -> icmp_echo). Or keep tcp_v4_rcv and change the trigger to `curl -s http://example.com >/dev/null`.
- [ ] **[major/wont-fire-or-empty]** _Or use BPF for a custom view (119-127)_ — no traffic trigger; on a quiet console the 5s window captures zero receives and all maps stay empty. **Fix:** Add "While this runs, generate receives in another terminal: `ping -c 5 8.8.8.8` and `curl -s http://example.com >/dev/null`." State expected `@tcp[eth0]: 6` etc., and caveat that fentry:ip_rcv may attach but not fire on some kernels — point at @tcp/@udp as the reliable signal.
- [ ] **[major/no-expected-output]** _Inspect per-CPU RX state / Adjust netdev_budget (137-146)_ — "Watch softnet_stat shift" never happens at idle (time_squeeze only moves under budget exhaustion), and the set-600/restore lines are contiguous so the box never runs at 600. **Fix:** Split into set / observe / restore: `old_budget=$(cat /proc/sys/net/core/netdev_budget); echo 600 | sudo tee /proc/sys/net/core/netdev_budget`, then under sustained RX load (`iperf3 -c <host> -P 16`) re-read `/proc/net/softnet_stat` col 3 (time_squeeze), then `echo "$old_budget" | sudo tee /proc/sys/net/core/netdev_budget`. State that on an idle host time_squeeze never moves.
- [ ] **[minor/missing-setup]** _Use ftrace to see the call chain (101-113)_ — blocking `trace-cmd record ... sleep 5` and `ping` are in one block, so a copy-paste reader records nothing; trace-cmd isn't installed by default. **Fix:** Add `# install if missing: sudo apt-get install -y trace-cmd` and prose: "In terminal 1 start the recorder; within the 5s window run the ping in terminal 2; then run `trace-cmd report`." Leave `head -100` as-is.
- [ ] **[minor/missing-why]** _Inspect per-CPU RX state (131-135)_ — `/proc/net/softnet_stat` prints zero-padded hex with no header; reader will misread time_squeeze as decimal. **Fix:** Add: "Every field is a 32-bit counter printed in hexadecimal (%08x), no header. Columns: processed, dropped, time_squeeze, ... Convert with `printf '%d\n' 0x<value>`."

#### day03 — The TX path: tracing a TCP packet from send()/sendmsg down through the qdisc to the NIC driver.

- [ ] **[major/wont-fire-or-empty]** _Trace a TCP send all the way through (108-121)_ — recorder backgrounded with `sleep 5 &` and the trigger lives in a second terminal with no stated timing; a slow reader captures no tcp_sendmsg tree. **Fix:** Run the trigger inside the recorded command: `sudo trace-cmd record -p function_graph -g tcp_sendmsg -O nofuncgraph-overhead -O funcgraph-tail bash -c 'echo hello | nc -q 1 example.com 80; sleep 1'` then `sudo trace-cmd report | head -200`.
- [ ] **[major/wont-fire-or-empty]** _Watch socket buffer accounting (125-129)_ — `ss -tim` on an idle box shows static near-zero values; Stage 2 (send buffer fills) is invisible without a sustained, rate-limited transfer. **Fix:** Constrain egress and run a long transfer: `sudo tc qdisc replace dev eth0 root tbf rate 1mbit burst 32kbit latency 50ms; iperf3 -c <remote-host> -t 30 &; watch -n1 'ss -tim dst <remote-host>'` (wmem_queued climbs toward sk_sndbuf; unacked = in-flight), then restore. Note loopback won't fill the buffer (no bottleneck).
- [ ] **[major/broken-command]** _Force a backlog and watch (144-146)_ — `iperf3 -c some-target` is an undefined placeholder needing a reachable server; tbf on eth0 only shapes eth0 egress, so a loopback substitute shows zero backlog. **Fix:** "On a second machine run `iperf3 -s`; then here run `iperf3 -c <that-host-IP> -t 30 &`. (Loopback won't work — tbf on eth0 only shapes eth0 egress.) Then `watch -n1 'tc -s qdisc show dev eth0'` and watch the `backlog ...b ...p requeues N` line climb."
- [ ] **[minor/missing-setup]** _Trace a TCP send (116)_ — `nc -q 1 8.8.8.8 80` needs outbound TCP/80 and a BSD/traditional nc (`-q` rejected by ncat); not stated. **Fix:** Add: "needs outbound TCP and a BSD nc (on ncat drop `-q 1`)." Prefer a guaranteed-reachable host: `echo "hello" | nc -w1 example.com 80`.
- [ ] **[minor/inconsistency]** _Force a backlog (restore) (80,148-151)_ — restore hardcodes `fq_codel`, but line 80 says the kernel default is still pfifo_fast; cleanup doesn't restore original state. **Fix:** Use `sudo tc qdisc del dev eth0 root` (drops to the real default), or capture `ORIG=$(tc qdisc show dev eth0 | awk 'NR==1{print $2}')` first and restore that. Stop calling fq_codel "the default."
- [ ] **[minor/missing-cleanup]** _Force a backlog (142-151)_ — 1mbit tbf throttles the reader's own SSH if connected over eth0; backgrounded iperf3 not cleaned up. **Fix:** Add warning: "this throttles ALL eth0 egress — run on a throwaway VM or non-management NIC." Bound the test (`-t 30`) or add `kill %1 2>/dev/null` alongside the qdisc restore.
- [ ] **[minor/no-expected-output]** _Inspect qdisc statistics (134-137)_ — "Drops, requeues, current backlog" all read 0 on idle; success criterion not framed. **Fix:** After line 137 add: "On an idle box `dropped`, `requeues`, and `backlog` all read 0 — that is expected. The next experiment forces `backlog` non-zero."

#### day04 — GRO/GSO/TSO segmentation offloads and how they hide per-wire-packet work from the stack.

- [ ] **[critical/broken-command]** _Watch GRO in action (106-122)_ — `iperf3 -c 8.8.8.8` fails (Google DNS runs no iperf3 server; iperf3 may be absent), so the GRO/ip_rcv histograms never populate. **Fix:** Use a server-less bulk download during the bpftrace window: `curl -o /dev/null https://speed.cloudflare.com/__down?bytes=1000000000`. - [ ] **[critical/broken-command]** _Per-segment counter (139-146)_ — `ethtool -S eth0 | grep -i tx_pkts` matches nothing (real field is tx_packets/tx_queue_N_packets); no load, no expected numbers, no kernel-side count for the ratio. **Fix:** Generate TX load (large upload), then `ethtool -S eth0 | grep -iE 'tx_packets|tx_queue.*packets'` (NIC counts) vs `cat /sys/class/net/eth0/statistics/tx_packets` (kernel). - [ ] **[major/weak-pedagogy]** _Watch GRO in action (106-122)_ — GRO is RX-side, but `iperf3 -c` (forward) sends OUT; inbound is just small ACKs, so gro_receive_skb/ip_rcv show no coalescing. **Fix:** Generate inbound bulk: `curl -o /dev/null http://<host>/bigfile` or `iperf3 -c <server> -R`. - [ ] **[minor/broken-command]** _TSO concept block (27-31)_ — `ethtool -k eth0 | grep tso` matches nothing yet comment claims it prints `tcp-segmentation-offload: on`. **Fix:** `ethtool -k eth0 | grep tcp-segmentation-offload`. #### day07 — ARP and the neighbour subsystem: the NUD state machine, TX-side neigh_lookup, and gc thresholds.

- [ ] **[critical/missing-cleanup]** _Statically pin a wrong MAC (114-124)_ — `ping 192.168.1.1` has no `-c`, so it runs forever and the `ip neigh del` undo never executes, leaving the gateway poisoned; a reader SSH'd over that gateway is locked out, with no warning. **Fix:** Bound the ping and warn: `ping -c 3 -W 1 192.168.1.1   # no replies — sent to a MAC nobody owns`. Add: "Do NOT do this for the gateway on the interface carrying your SSH session — pin a non-gateway peer or use the console."
- [ ] **[major/missing-cleanup]** _Watch ARP packets (81-89)_ — backgrounded tcpdump never stopped; no count/timeout. **Fix:** Add after the ping: `sudo pkill tcpdump   # stop the background capture` (optionally also `sudo timeout 5 tcpdump ... &`).
- [ ] **[major/no-expected-output]** _Trace neighbour state changes (94-98)_ — prints nud_state/new as raw decimals; chapter names states but never gives numeric bitmask values. **Fix:** Add decoder: NUD bitmask 1=INCOMPLETE, 2=REACHABLE, 4=STALE, 8=DELAY, 16=PROBE, 32=FAILED. Sample: `# update: state=4 new_state=8 (STALE -> DELAY)`. Optionally print `%x`.
- [ ] **[major/missing-setup]** _Experiment / What to break (66-133)_ — every command hardcodes `eth0` and `192.168.1.1`; verbatim runs fail on predictable-named NICs / wrong gateway. **Fix:** Add a setup block: `IFACE=$(ip route show default | awk '{print $5; exit}'); GW=$(ip route show default | awk '{print $3; exit}'); echo "iface=$IFACE gateway=$GW"`, then use `dev "$IFACE"` and `ping -c 1 "$GW"`.
